# Новости сайта (журнал изменений)

## Когда использовать

- Изменение сайта нужно показать игрокам в блоке «Новости сайта» на главной (`#homeNews`).
- Нужно поправить, скрыть, переупорядочить или добавить запись журнала.
- Не путай: «Новости Зоны» (новости игры, `news.js`, `ZONE_NEWS`, баннеры событий) - скилл **zone-news**.
  Автопункты «Добавлен гайд» генерируются отсюда, но сами гайды - скилл **guides**.

## Файлы

- `site-news.json` - **источник правды**, редактируется руками и ботом CI. В `.prettierignore`.
- `build-changelog.js` - импортирует новые коммиты и опубликованные гайды в `site-news.json`, затем
  перезаписывает массив `window.CHANGELOG=[...]` в `changelog.js`. Здесь же списки `SKIP`, `SKIP_GUIDES`, `TYPOS`.
- `changelog.js` - **генерируется** (данные `window.CHANGELOG`) + в том же файле IIFE, которая рисует блок
  в `#homeNews` (подписи типов, «Вся история», метка NEW). Массив руками не правь - перезапишется. Файл в
  `.prettierignore` и в ignores `eslint.config.mjs`.
- `index.html` - контейнер `#homeNews`, подключает `changelog.js`. `build.js` (`PRERENDER["index.html"]`)
  выполняет `changelog.js` и вшивает готовую разметку блока в HTML.
- Стили: `styles.css`, классы `.news-entry`, `.news-compact`, `.news-tag-new|up|fix`, `.news-toggle`, `.news-items a`.
- `.github/workflows/pages.yml` - шаг Build (`node build-changelog.js && ...`) и шаг «Save imported site news».

## Схема `site-news.json` (по `validate()` в build-changelog.js)

```json
{
  "version": 1,
  "entries": [
    {
      "date": "2026-11-01",
      "title": "Мастерство в картах «21»",
      "items": [
        ["new", "В «Информации» → «Прогресс по уровням» появилась вкладка «Карты «21»»: ..."],
        ["up", "В виде «Таблицы» таланты теперь во всю ширину ..."]
      ]
    }
  ],
  "importedSources": ["0e1b91752c0a4430575972e110142cd578b67680", "guide:vylazki"],
  "migrated": true
}
```

- `version` - строго `1`. `entries`, `importedSources` - массивы, иначе сборка падает (и деплой тоже).
- `date` - строго `ГГГГ-ММ-ДД`, реальная дата.
- `title` - непустая строка. Вставляется как HTML (`<b>` + title).
- `items` - массив пар `[тип, html]`, тип только `new` | `up` | `fix`. На сайте подписи:
  `new` - «Новое», `up` - «Улучшено», `fix` - «Исправлено» (CSS выводит их капсом). Текст пункта - HTML (innerHTML):
  ссылки работают, а буквальные `<` и `&` надо экранировать.
- `hidden` - необязательный, только `true`/`false`; `true` убирает запись с сайта, но оставляет в файле.
- `importedSources` - полные 40-символьные хэши уже импортированных коммитов и `guide:<папка>` уже объявленных гайдов.
  Не удаляй из него строки: коммит/гайд импортируется повторно.
- `migrated: true` - флаг одноразовой миграции, не трогай. Других полей скрипт не знает; лишние поля в записях
  молча отбрасываются при выводе в `changelog.js`.
- Порядок на сайте: по `date` по убыванию; при одинаковой дате - порядок в массиве `entries` (новые импорты
  вставляются в начало). Первая запись показана целиком (3 пункта + «Ещё N изменений»), остальные свёрнуты,
  после 3-й - под «Вся история». Метка NEW: если дата первой записи новее запомненной (`localStorage.gameHelperNewsSeen`).

## Как коммит становится записью (`build-changelog.js`)

1. `git log --no-merges` по всей истории, дата - **дата автора** коммита по Москве (не дата merge/push).
2. Пропускается коммит, если: хэш есть в `importedSources`; хэш начинается с префикса из `SKIP`; в сообщении
   где угодно есть `[skip news]` (регистр не важен); нет ни одной строки-тега.
3. Строка-тег: любая строка сообщения (включая первую), которая целиком соответствует
   `/^\s*(new|upd|update|up|fix)\s*:\s*(.+?)\s*$/i`. `upd:`/`update:` = `up:`; регистр тега не важен (`Upd:` ок).
   Строки с маркером (`- new:`, `* fix:`) **не** распознаются. Каждая строка-тег = один пункт, типы можно смешивать.
4. Обработка текста пункта: `TYPOS` (замены опечаток, сейчас хэллуин -> хэллоуин), длинное тире -> «-»,
   первая буква заглавная (ведущие теги вроде `<a>` не мешают), `"прямые"` -> `«ёлочки»` вне HTML-тегов,
   одна точка в конце убирается (многоточие нет).
5. `title` записи = первая строка сообщения (с той же автозаменой, кроме удаления точки), если она сама не тег;
   иначе «Обновление».
6. Группировка: коммиты с одинаковыми `date` + `title` сливаются в одну запись, пункты старых коммитов выше.
   Разные заголовки в один день = разные записи.
7. Гайды: каждая `guides/<папка>/index.md` с `title`, без `draft: да|true|yes|da`, не в `SKIP_GUIDES` и не в
   `importedSources` даёт пункт `new` «Добавлен гайд <a href="/guide/<папка>">«Название»</a>. Автор - X»
   с датой первого появления файла в main (first-parent), запись «Новый гайд»/«Новые гайды». Не дублируется, если
   ссылка `/guide/<папка>` или `«Название»` уже есть в какой-либо записи.
8. Новые записи - в начало `entries`, хэши - в `importedSources`. Записи, однажды импортированные, из git больше
   не пересчитываются: дальше правится только `site-news.json`.

## CI и `git pull`

- Деплой (каждый push в main) запускает `node build-changelog.js` (без `--dry`). Если `site-news.json` изменился,
  шаг «Save imported site news» коммитит его в main от `github-actions[bot]` с сообщением
  «Сохранены новости сайта [skip news] [skip ci]» (обычный push). `changelog.js` в этот коммит не входит - в репо
  он отстаёт до следующей локальной генерации, на сайте всегда свежий.
- **После любого push с тегами в main появится коммит бота. Перед следующим push - `git pull --rebase`**, иначе
  push отклонят (non-fast-forward). Если ты правил `site-news.json`, а бот тоже - при конфликте оставь обе стороны
  (его новые записи в начале `entries` + объединённый `importedSources`), JSON должен остаться валидным.
- Если пока шла сборка, в main успел прийти другой push, push бота упадёт и этот деплой не выложится; следующий
  запуск импортирует то же самое заново - это нормально.

## Безопасный просмотр результата

- `node build-changelog.js --dry` - **ничего не пишет** (проверено: ветка `if (DRY)` только печатает), выводит
  строку «новых записей N, опубликовано M» и итоговый JSON `site-news.json`. Используй, чтобы проверить, как
  импортируются твои локальные коммиты (они должны быть уже закоммичены).
  Пример: `node build-changelog.js --dry | tail -n +2 | diff site-news.json -` (лишняя пустая строка в конце - норма).
- Без `--dry` скрипт пишет `site-news.json` (импортирует **все** неимпортированные локальные коммиты, в т.ч. ещё
  не запушенные) и `changelog.js`. Так же делают `npm run build` (в `package.json` он начинается с
  `build-changelog.js`, хотя DEVELOPMENT.md пишет иначе) и `dev.js` (при каждом сохранении `site-news.json`).
  Если после этого переписать (amend/rebase/squash) уже импортированные локально коммиты - в CI они импортируются
  второй раз под новыми хэшами. Не переписывай их, или откати автоимпорт перед коммитом.

## Сценарии

**Объявить новую функцию через коммит** (основной путь):
```
Мастерство в картах «21»

new: В <a href="/info">«Информации»</a> появилась вкладка «Карты «21»»: таблица и график мастерства
up: В виде «Таблицы» цифры больше не налезают друг на друга
fix: На телефоне подсказка на графике не уходит за край экрана
```
Первая строка - заголовок записи для игроков (не «Fix bug»), каждый тег - на отдельной строке, весь пункт в одной
строке (перенос обрежет текст). Проверь `--dry`, запушь, затем `git pull --rebase`.

**Коммит не для новостей** (рефакторинг, данные, мелочь): просто не пиши строк-тегов. Если в сообщении нужна
строка, начинающаяся с `fix:`/`new:`/`up:`, добавь `[skip news]`.

**Скрыть уже импортированное**: в `site-news.json` удали пункт/запись или поставь записи `"hidden": true`.
`SKIP` на импортированные коммиты не действует. Хэш из `importedSources` не удаляй.
**Скрыть ещё не импортированный коммит** (уже запушен в ветку/PR, сообщение не переписать): добавь префикс хэша
в `SKIP` в `build-changelog.js` с комментарием почему (как с `"4f0c2d1"`). Гайд - папку в `SKIP_GUIDES`.
Опечатку в уже запушенном сообщении - пара в `TYPOS`.

**Поправить/переименовать запись**: правь `title`/`items`/`date` прямо в `site-news.json` (отступ 2 пробела,
как `JSON.stringify(..., null, 2)`). Объединить две записи - перенеси пункты в одну, другую удали.

**Добавить запись вручную без коммита-источника**: вставь объект в `entries` (на своё место по дате; при равной дате
выше = выше на сайте). В `importedSources` ничего не добавляй. Сообщение такого коммита - без тегов, иначе получится
дубль. Пример в истории: коммит «Добавить новость о мастерстве в картах «21»».

После ручной правки `site-news.json` `changelog.js` обновится в CI сам. Хочешь увидеть локально - запусти
`node build-changelog.js` (пишет файлы, см. выше) и закоммить `changelog.js` вместе с `site-news.json`; проверь
`git diff site-news.json`, что импортировалось только ожидаемое.

## Стиль пунктов

- Пиши для игроков, по-русски, без техно-жаргона (не «рефакторинг», «CLS», «CSP», «PR», имена файлов): что
  появилось/изменилось и где. Хорошо: «Сравнение игроков открывается из <a href="/top100">Топ-100</a> - кнопкой
  «Сравнить игроков»». Плохо: «Добавлен compare.js».
- `new` - новая возможность/раздел; `up` - улучшение существующего; `fix` - было сломано, теперь работает
  («...больше не сдвигаются при загрузке», «...снова открываются»).
- Названия разделов, вкладок, кнопок, комплектов - в «ёлочках»: «Информация», «Моё место», «Расчёт по жетонам».
  Путь по интерфейсу - через «→». Только дефис «-», без длинного тире. Без точки в конце пункта.
- Ссылки - относительные, без `.html`: `/calculator`, `/top100`, `/compare`, `/factions`, `/info`,
  `/info-bosses`, `/guides`, `/guide/<папка>`. Атрибуты - в двойных кавычках (в JSON - `\"`).
- `title` - короткая суть дня: «Мобильное меню и порядок в интерфейсе», «Счётчик урона «Мой арсенал» в калькуляторе».
  Не «Исправления» - если можно назвать конкретнее.
- Один пункт - одна мысль, 1-2 предложения; несколько мелочей можно собрать в «...плюс небольшие косметические улучшения».

## Проверка

- `node build-changelog.js --dry` - без ошибок `site-news.json: ...` (это ошибки `validate()`, в CI они валят деплой),
  ожидаемое «новых записей N».
- `node -e 'JSON.parse(require("fs").readFileSync("site-news.json","utf8"))'` после ручной правки.
- Глазами: главная `/`, блок «Новости сайта» (справа от «Новостей Зоны» на широком экране): дата, заголовок,
  подписи «Новое/Улучшено/Исправлено», ссылки кликаются, «Вся история» раскрывает старые записи. Локально - через
  `dev.js` (см. site-dev), прод - https://heart-of-the-zone.ru/.
- Общие тесты/линт/формат/скриншоты и коммит - по скиллу **verify-and-ship**.

## Связанные скиллы

- **zone-news** - «Новости Зоны» (новости игры) в соседней колонке главной.
- **guides** - публикация гайдов (их автопункты «Добавлен гайд» приходят сюда).
- **site-dev** - сборка, `dev.js`, `build.js`, CSS главной.
- **verify-and-ship** - проверка перед публикацией, коммит и PR.
